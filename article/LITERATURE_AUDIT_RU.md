# Финальный аудит литературы и границ новизны

**Дата заморозки:** 12 октября 2026 г.

## 1. Назначение

Этот аудит выполняется непосредственно перед написанием финальной версии статьи. Его задача — не увеличить число ссылок, а:

1. проверить библиографические реквизиты по первичным или издательским источникам;
2. отделить нормативные документы от научных работ и патентного уровня техники;
3. найти наиболее близкие работы по каждой составляющей метода;
4. исключить завышенные формулировки новизны;
5. зафиксировать новые публикации 2025–2026 гг., появившиеся после ранних версий обзора;
6. подготовить стабильный набор ссылок, который больше не меняется без явного повторного аудита.

Машиночитаемый реестр: `article/references_verified.json`.

Сравнительная матрица: `article/LITERATURE_MATRIX_RU.md`.

## 2. Методика поиска

Проверены страницы 3GPP Portal, NIST, IEEE Xplore/официальные метаданные конференций, ACM/DBLP, Springer, Elsevier ScienceDirect, PMLR, CEUR-WS, arXiv и Google Patents.

Целевые группы запросов:

- 5G Core / SBA security / SBI integrity;
- Service Communication Proxy / SCP anomaly detection / SCP integrity;
- NRF / NF discovery / profile integrity;
- HTTP/2 anomaly detection in 5G SBA;
- state auditing / event monitoring / provenance / access-control analysis;
- concept drift / distribution shift in 5G Core;
- sequential change detection / CUSUM / ADWIN;
- conformal martingales / e-process / e-detector;
- API schema / OpenAPI / structural anomaly detection;
- end-to-end SBI integrity / before-after SCP comparison;
- 2025–2026 5G Core anomaly detection and adversarial evaluation.

Аудит является систематизированным поиском ближайшего уровня техники, но не объявляется формальным PRISMA systematic review: не выполнялась библиометрически исчерпывающая процедура дедупликации по всем коммерческим индексам.

## 3. Нормативная база: версии необходимо закрепить

В предварительной статье номера TS указаны без версии. Для финального текста это следует исправить.

Рекомендуется закрепить **Release 18** как стабильную нормативную базу статьи:

| Документ | Назначение | Закрепляемая версия |
|---|---|---:|
| 3GPP TS 23.501 | архитектура 5GS | **18.12.0** |
| 3GPP TS 29.500 | техническая реализация SBA | **18.10.0** |
| 3GPP TS 29.501 | принципы определения сервисов | **18.7.0** |
| 3GPP TS 29.510 | сервисы NRF | **18.11.0** |
| 3GPP TS 33.501 | архитектура и процедуры безопасности 5GS | **18.12.0** |
| 3GPP TS 33.522 | SCAS для SCP | **18.0.0** |

Почему не следует просто цитировать «последнюю версию»: к октябрю 2026 г. портал уже содержит Release 19/20 для части документов. Смена версии после рецензирования превращает ссылку в движущуюся цель и может создавать ложное впечатление, что стенд Open5GS проверял совместимость с Release 20.

### Новый нормативный контекст

После подготовки исходного списка появился специализированный **3GPP TS 29.570 “5G System; Service Communication Proxy Services; Stage 3”**. Для Release 19 на дату аудита доступна версия **19.3.0**.

Его целесообразно добавить в раздел нормативного контекста как более новый стандарт SCP-сервисов, но **не** использовать как основание для утверждения, что испытанный Open5GS v2.7.6 реализует TS 29.570.

## 5. Сильнейший патентный предшествующий уровень техники

WO2025250353A1 (Oracle International Corp) имеет приоритет **28.05.2024** и публикацию **04.12.2025**.

Это не периферийная ссылка, а один из наиболее близких источников к заявляемой задаче. В нём описаны:

- копия SBI-сообщения до прохождения SCP;
- копия соответствующего сообщения после прохождения SCP;
- корреляция двух копий;
- сравнение значений атрибутов;
- возможность сравнения хешей значений;
- исключение атрибутов, которые SCP правомерно изменяет;
- сценарий компрометации SCP.

Следовательно, текущая статья **не должна** заявлять как новизну сам принцип «получить две копии сообщения по разные стороны SCP и сравнить их целостность».

Отличие текущего исследования следует искать в другом: последовательной многоканальной обработке рассогласований, устойчивости к разреженным событиям/дрейфу, ортогональных представлениях и экспериментальной процедуре.

Дополнительное важное ограничение: патент прямо рассматривает компрометированный SCP, тогда как текущая живая Open5GS-проверка Stage 21 доверяет штатному SCP и изменяет только потребительскую копию **после** общего SCP→NRF пути. Поэтому нельзя утверждать, что наш стенд экспериментально проверил более сильную модель Oracle.

## 6. Новые источники 2025–2026 гг., которые следует учесть

### 6.1. Большой поток KPI в реальном 5G Core

Cho et al., “A Framework for AI-Based Large-Scale Time-Series Anomaly Detection in 5G Core Networks”, ICTC 2025, pp. 509–514, DOI:
**10.1109/ICTC66702.2025.11388910**.

Работа включает PoC в real-world 5G core и раннее обнаружение по многочисленным KPI. Её полезно добавить, чтобы не создавать впечатление, что реальная 5GC-проверка anomaly detection уникальна сама по себе.

### 6.2. Современная многомерная conformal change detection

Eliades, Papadopoulos, 2026:

**Multivariate Change-Point Detection Using Feature-Based Inductive Conformal Martingales**, PMLR 329:633–651.

Добавить как свежую методологическую работу по последовательному многомерному обнаружению.

### 6.3. Fixed-reference conformal shift detection

Shaer et al., ICML 2026:

**Testing For Distribution Shifts with Conditional Conformal Test Martingales**, PMLR 306:109447–109469.

Особенно релевантна концептуально, потому что показывает современную линию работы с **фиксированным эталонным набором** и проблемой загрязнения reference set. Это статистический, а не SBI/SCP reference, поэтому отождествлять два вида «эталона» нельзя.

### 6.4. Свежий обзор атак 5G SA

Gong et al., Computer Networks 270 (2025), 111545, DOI:
**10.1016/j.comnet.2025.111545**.

Полезен как обновлённый фон угроз, но не является ближайшим алгоритмическим конкурентом.

## 7. Что теперь нельзя называть научной новизной

После финального аудита следующие формулировки следует исключить:

- «первый детектор на SCP»;
- «первый метод контроля целостности сообщений через SCP»;
- «новый e-detector/e-process для последовательного обнаружения»;
- «первый структурный анализ SBI/API»;
- «первая система обнаружения аномалий на реальном/функциональном 5G Core»;
- «первый метод работы с concept drift в 5GC»;
- «первый подход к adversarial evaluation детектора 5GC».

Все эти направления имеют явных предшественников.

## 8. Что остаётся защищаемым вкладом

### 8.1. Алгоритмико-архитектурная композиция

Защищаемая формулировка:

> многоканальная последовательная схема контроля целостности 5G SBA, объединяющая направленную парную сверку наблюдений, память разреженных событий, включаемую по устойчивости наблюдаемого режима, value-independent структурную сверку и stable-value семантическую сверку.

Ни один из этих элементов по отдельности не следует объявлять новым.

### 8.2. Failure-driven экспериментальная методология

Сильнейший вклад статьи — не только конечная полнота, а опубликованная причинная последовательность:

1. успех на близком генераторе;
2. провал против сильных последовательных методов при сдвиге распределения;
3. выделение механизма потери знака;
4. направленная статистика;
5. перенос на живой Open5GS;
6. обнаружение разреженной слепой области;
7. новый разреженный канал;
8. обнаружение структурной слепой области;
9. ортогональный структурный канал;
10. обнаружение семантической слепой области;
11. новый семантический канал;
12. замороженная 128-запусковая репликация;
13. единая абляция;
14. анализ времени до обнаружения;
15. измерение накладных расходов;
16. формальная модель доверия и отрицательная реляционная граница.

### 8.3. Эмпирический вклад

Сильная формулировка:

> Эксперименты показывают, какие именно классы рассогласований последовательно остаются невидимыми для численного, структурного и семантического представлений и как добавление ортогональных каналов закрывает наблюдавшиеся отказные режимы без ретроспективной настройки на итоговых блоках.

Это сильнее и безопаснее, чем утверждение абсолютного алгоритмического первенства.

## 9. Остаточная граница новизны

После аудита наиболее близким конкурентом к архитектурной идее является Oracle WO2025250353A1, а к SCP runtime detection — 5G-RAD.

Поэтому окончательная статья должна подчёркивать:

- **не** «мы впервые сравниваем SBI до/после SCP»;
- **не** «мы впервые мониторим через SCP»;
- а **«мы исследуем последовательную обработку парных integrity-рассогласований при дрейфе, разреженности и различных представлениях данных, с failure-driven frozen validation на Open5GS»**.

По целевому поиску до 12.10.2026 не найден источник, который в одной работе сочетал бы всю эту композицию и экспериментальный протокол. Это утверждение необходимо сопровождать словами **«в рассмотренном корпусе»** или **«по результатам проведённого аудита»**.

## 10. Рекомендуемая формулировка раздела “Научная новизна”

> В отличие от работ по мониторингу 5G Core через SCP, статическому анализу API, графам происхождения, обнаружению временных аномалий и сквозной сверке атрибутов SBI, предлагаемая схема рассматривает рассогласование независимых наблюдений как многоканальный последовательный процесс. Численный направленный канал дополняется памятью разреженных событий, структурным представлением JSON и семантической сверкой стабильных скалярных путей. Новизна относится к данной композиции и к процедуре её поэтапной проверки, а не к отдельным составляющим CUSUM/e-process, SCP-monitoring, hashing или structural API analysis. По результатам проведённого до 12.10.2026 аудита ближайших работ не выявлено публикации, одновременно реализующей перечисленную комбинацию с замороженной слепой валидацией на штатном пути Open5GS SCP→NRF и последующей независимой масштабной репликацией.
